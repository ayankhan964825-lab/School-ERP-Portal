# Proactive Planning and Alignment Rule

**ALWAYS check `phase.md` before starting any task or reacting to a user's idea.**

Whenever the user explains a new feature, suggests an idea, or asks you to start working on a module:
1. **Stop and cross-check `phase.md`**: Do not start implementing or asking redundant questions immediately. First, read `phase.md` to see if the feature/idea is already planned, where it fits in the timeline, and what specific tasks are associated with it.
2. **Review Core Files**: If necessary, also cross-check the core schema (`prisma/schema.prisma`) and other foundational architecture files to ensure the idea aligns with the established data models and structures.
3. **Acknowledge and Map**: In your response, explicitly acknowledge where the user's idea fits within `phase.md` (e.g., "This aligns perfectly with Task 10.5 in phase.md..."). 

**Goal**: Minimize redundant explanations from the user and ensure all development efforts are strictly aligned with the master plan.
